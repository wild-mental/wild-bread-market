### GRIP-08 · 원지표 원본은 보관하되 환산식은 비공개 (T8 · CORE)

### GRIP-09 · 주간 랭킹은 참여 회차 수를 상위 기준으로 둔 계단식(1차·2차…) 랭크 (T9 · CORE)
- 결정(사용자 표현): "참여 회차 수를 고정된 숫자로 두지 말고, 주간 실제 진행된 회차 수를 기준으로 하며, 모든 회차에 참여한 사람들을 대상으로 1차 랭크, 1회 미참자 대상 2차 랭크를 매기는 방식으로 참여유도를 최대화하면서도 예측에 참가한 전원이 랭크에 들어갈 수 있도록 함. A 안에서 참여 회차 수를 동점처리 기준이 아니라 절대적인 상위 기준으로 뽑아 올린 규칙에 해당함."
- 구체화:
  - 주 경계는 **월~금**.
  - **최소 참여 회차라는 고정 기준을 두지 않는다.** 대신 그 주 실제 회차 수 `N`을 기준으로 **결석 수(= N − 참여 수)** 로 티어를 나눈다. 결석 0회 = 1차 랭크, 1회 = 2차 랭크, 2회 = 3차 랭크 … 이므로 **참가자 전원이 어딘가의 랭크에 든다.**
  - 정렬 순서: ① 참여 회차 수(많은 순 — 티어) ② 정확도 ③ 먼저 제출한 순.
- 근거: 고정 기준(예: 3회차)은 미달자를 랭킹에서 완전히 배제해 참여 동기를 끊는다. 계단식은 배제 없이도 전 회차 참여가 항상 더 유리하게 만들어 참여 유도를 극대화한다.
- **파생 확정 — `N`은 "유효 회차" 수다.** GRIP-06에서 부분 미수집 회차는 전체 무효(VOID)로 정했으므로, 애초에 채점될 수 없던 회차를 결석으로 세면 부당하다. 따라서 **무효 회차는 `N`에서 빼고 결석 계산에서도 제외한다.**
- 스키마 영향: `weekly_rankings`에 확정 시점 값을 박아 저장한다 — `valid_rounds`(그 주 유효 회차 수 N) · `participated`(참여한 유효 회차 수) · `tier`(N − participated, 0이 1차 랭크) · `hits`·`judged`·`accuracy` · `rank_in_tier` · `confirmed_at`. `unique (week_start, user_id)`. 나중에 재계산해도 과거 순위가 흔들리지 않게 하려는 것이다.
- T10 연계: 리워드를 1차 랭크만 대상으로 할지, 티어별로 줄지가 아직 미정 → T10에서 정한다.

### GRIP-09a · (GRIP-09 정정) 랭크는 티어로 분절되지 않고 1위부터 연속으로 매긴다 (T9 · CORE)
- 정정: GRIP-09의 `rank_in_tier`(티어 안에서의 순위)를 폐기하고 **주 단위 연속 순위 `rank`** 로 바꾼다. 티어는 **정렬 기준**일 뿐 순위표를 나누지 않는다.
- 결정(사용자 표현): "1차 2차 랭크가 분절된게 아니라, 1위부터 순차 연결되어서 다뤄지도록 하고"
- 동작 예시 (그 주 유효 회차 N=5):
  - 결석 0회 그룹 3명 → 순위 **1·2·3** (그룹 안에서는 정확도 → 제출시간 순)
  - 결석 1회 그룹 4명 → 순위 **4·5·6·7**
  - 결석 2회 그룹 → 순위 **8** 이후
- 따라서 "상위 5명"은 티어를 가로지른다. 위 예시에서는 결석 0회 3명 전원과 결석 1회 그룹 상위 2명이 해당한다.
- 스키마 영향: `weekly_rankings.rank_in_tier` → **`rank`**(연속 순위). 동점 처리가 ①참여 회차 수 ②정확도 ③제출시간으로 완전히 결정적이므로 `unique (week_start, rank)`를 걸 수 있다.

### GRIP-10 · 리워드는 주간 상위 5명에게 쿠폰코드 수동 지급 (T10 · CORE)
- 결정: 주간 연속 순위 **상위 5명**에게 리워드(현재 목업: 7일 프리미엄 브레드 구독권)를 **운영자가 쿠폰코드를 발급해 수동 지급**한다. 카페24 쿠폰 API 자동 발급은 이번 범위에서 제외한다.
- 근거: 카페24 쿠폰 API를 쓰면 앱 권한(scope) 추가와 재심사가 따라와 DB 연동 범위를 넘어선다. 수동 지급은 지급 건수를 통제할 수 있어 MVP 단계에 맞는다. 자동 발급은 운영이 안정된 뒤 별도로 붙인다.
- 지급 대상이 티어를 가로지르므로(GRIP-09a), 결석이 있어도 상위 5위 안에 들면 받는다.
- 스키마 영향: `rewards` 신설 — `week_start`·`user_id`·`rank`·`reward_type`·`code`·`status`(`pending`/`issued`/`claimed`/`expired`)·`issued_at`·`claimed_at`·`expires_at`, **`unique (week_start, user_id)`** 로 한 주 중복 수령을 막는다.
- 미결(사람 작업): 경품 고지 의무·제세공과금 해당 여부는 법적 확인이 필요하다 → `HUMAN_TODO`.

### GRIP-08a · (GRIP-08 보완) 정정값은 공개 컬럼에 포함한다
- 배경: GRIP-07의 정정 이력 칸을 추가하면서 GRIP-08의 "공개 컬럼 4개" 규칙과 부딪혔다. `AGENTS.md` 규범 13은 컬럼을 늘리려면 규칙을 먼저 고치라고 정하고 있다.
- 결정: `corrected_value`·`corrected_at`을 **공개 컬럼에 포함**한다. 공개 컬럼은 6개가 된다.
- 근거: 정정값은 `value`와 같은 종류의 브레드 지수값이라 원지표나 환산식을 추가로 노출하지 않는다. GRIP-08이 막으려던 것은 원지표 원본과의 대조를 통한 공식 역산이며, 정정값은 여기에 해당하지 않는다. 오히려 값이 정정된 사실을 사용자에게 숨길 이유가 없다.
- 규범 갱신: `AGENTS.md` 규범 13의 공개 컬럼 목록을 6개로 고쳤다.
